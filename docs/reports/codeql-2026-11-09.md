## Automatic pull-request scope and full-main requirement

The real job logs computed PR diff ranges, generated `codeql-action/pr-diff-range`
and applied CodeQL's automatic `exclude-from-incremental` query filtering. PR
results therefore cover changed-line alerts, not every pre-existing defect, even
though the logs show nonempty extraction across the repository. The 50/103/23 rule
counts above are this PR-mode observation, not full-main query totals. No project
path/query exclusion was configured.

A push to `main` is the supported non-PR full-scan path. Its genuine analyses and
all default-branch alerts must be inspected after merge; discovered defects need
focused corrections before repository-wide acceptance. No internal feature-flag
bypass, synthetic SARIF or suppression is used. See [GitHub's incremental-analysis
scope](https://docs.github.com/en/code-security/how-tos/find-and-fix-code-vulnerabilities/scan-from-the-command-line/incremental-analysis)
and [the documented PR alert change](https://github.blog/changelog/2025-05-28-incremental-security-analysis-makes-codeql-up-to-20-faster-in-pull-requests/).
