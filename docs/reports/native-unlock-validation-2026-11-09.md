# Native account unlock validation — 2026-11-09

The first 0.4.0 release attempt failed on Windows in job 129524058336 (run 42723755846), at `account-session.ts` after submitting **Unlock or create workspace**. Registration and recovery-code handling had already succeeded. The five-second workspace-heading expectation started immediately after the click; the helper did not observe whether browser PBKDF2 or the native unlock request had completed, failed or remained pending. The original job did not retain the relevant API status or UI notice, so the underlying Windows delay/failure is not proven.

The helper now waits for the real POST `/private/unlock` response, requires HTTP 200 and session `unlocked: true`, then applies the unchanged five-second workspace rendering assertion. Browser key derivation and server vault creation/encrypted snapshot remain required. This synchronizes a real asynchronous operation; it does not retry, accept an error, change cryptographic work, or widen the existing 60-second native journey. Default bounded Playwright response waiting applies within that same overall journey.

A regression holds an actual accepted unlock response, verifies the UI remains on the unlock screen with its control disabled and no workspace heading, then releases it. There are no sleeps or blind retries. This runs across Chromium, Firefox and WebKit. Native failures now log only bounded synthetic window state, JavaScript error classes and fixed-route service status codes, without request bodies, keys or cookies. A genuine error status fails at the API proof rather than later appearing as an unexplained missing heading.

Local validation: actual existing Windows 0.4.0 packaged executable and bundled frozen service passed the complete native source/history/inspection/catalog/lock journey in **7.8 seconds**; real unlock HTTP 200/session proof took **171 ms**. This does not reproduce the original hosted delay. The three-engine private suite passed **12/12**, including the new held-response cases. TypeScript/Vite, exact source-map freshness and five release-contract tests passed. No product source or private-store schema changed; the large Monaco build warning remains.

Hosted exact-source Validate/platform packaging and a new three-platform draft release build remain required before publication. The existing 0.4.0 release is unpublished; published older releases must remain untouched. This report does not claim a timing or operating-system root cause absent original evidence.
