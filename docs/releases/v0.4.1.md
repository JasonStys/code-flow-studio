# Code Flow Studio 0.4.1 — bounded reports and safe shutdown

By Jason Stys. This source prepares a hotfix; a new downloadable release requires
successful exact-source validation, full-main CodeQL review and three-OS native
package acceptance. Published 0.4.0 assets and tags remain unchanged.

The native account service gives HTTP work five seconds to drain, then cancels
and joins its own remaining request tasks before normal vault sealing. Real
offloaded disk operations and authorized local account/provider transitions finish
under the existing request mutex before cancellation is reported, including
repeated cancellation. Unlock/lock, provider destination/key/consent publication,
deletion, logout and recovery reset retain coherent local state. Request bodies,
AI calls and arbitrary network waits remain cancellable.

Actual native acceptance now requires numeric HTTP-drain observations, completed
workspace/lifespan/server/main milestones and absence of both owned service and
bootloader PIDs, as well as the existing account/editor/privacy/lock checks.
The [native-drain report](../reports/native-http-drain-2026-11-10.md) records the
real held-request, snapshot/restore and cancellation controls. The five-second
HTTP budget is not a universal process-exit guarantee: critical disk/container
cleanup must finish safely, and failed cleanup preserves recovery data. No force
exit, skipped sealing, test retry or increased native deadline is introduced.

The fixed JavaScript/TypeScript worker bridge opens each native JSON report once,
checks that descriptor's regular-file/size metadata, caps the bytes actually read
at eight MiB plus one sentinel byte, and closes it even on malformed JSON or I/O
errors. Path replacement cannot redirect an already opened descriptor; a stale
small size observation cannot authorize an unbounded read. This does not claim an
atomic snapshot against a process rewriting the same open file in place.

The development demo-contract regex uses disjoint escaped/unescaped alternatives,
removing exponential ambiguity. Original demo equality checks remain, with long
unterminated adversarial regressions added. These are the two actual findings in
the first full-main CodeQL scan, separately documented in the dated fix report.

The corrected distributed source is `runner/node_checks.cjs`. The worker Dockerfile
copies it to `/opt/node_checks.cjs`; build the reviewed worker with
`docker build -t code-flow-worker:0.4.1 runner`. The new image tag prevents the
controller from silently using the older 0.4.0 worker. No Docker repair or direct
host-execution fallback is introduced.

Desktop packages also ship that file as `resources/runner/node_checks.cjs` (inside
the application bundle's resources directory on macOS), together with the worker
Dockerfile and locked analyzer manifests. Native acceptance now compares its
SHA-256 with the reviewed checkout, in addition to the existing real account,
editor, source-inspector, catalog, sandbox and lock journey. A bundled resource is
not an already installed Docker image; compiler execution still needs an approved,
working local engine and an explicitly built matching worker.

Product/runtime/UI/npm/Python/installer and worker metadata are 0.4.1. Account,
vault, database, report and consent schemas are unchanged; no user-store migration
is added. Old releases remain available for rollback. Builds remain unsigned;
existing OS protections and separate local/private-data limits still apply.

Release automation now requires current exact-main successful push runs for
Validate, Desktop packages and CodeQL, three processed error-free CodeQL categories
with actual positive rule counts, and zero open main alerts. It creates a fresh
draft only after complete bounded release lookup proves the version unused.
Uploads bind the prepared numeric release ID, exact source, native acceptance
receipt, embedded provenance, fixed worker bytes and checksums; existing assets
are never overwritten. Release build/uploads run serially to avoid relying on
concurrent asset-state visibility. The final job rechecks security and all twelve
platform assets, then preserves the draft for independent downloaded Windows
installer acceptance and an explicit release-owner publication decision.
