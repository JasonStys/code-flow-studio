# Code Flow Studio 0.4.3 — C# coverage exit preservation

By Jason Stys. This source update corrects C# instrumented coverage. Hosted
compiler, security and native-package checks passed for the reviewed source; see
the [dated validation report](../reports/csharp-coverage-2026-11-10.md) for exact
sources, runs and measurement limits. No 0.4.3 download has been published.

The new worker retains a C# target's actual exit status separately
from Coverlet's collector status. Normal compilation and approved-case results
remain independent of instrumented coverage. Current validation must distinguish
expected exits 0, 1, 2, 7 and 255 from an unexpected application fault, including
execution through the authenticated API and encrypted-history recovery.

Product, runtime, UI, package and worker-image identities advance to 0.4.3. New
packages must include the reviewed `csharp_coverage_bridge.py` resource and match
its source digest during actual packaged-application acceptance. Metadata schema
1 keeps its existing Node-analyzer-only `worker_sha256` field; the exact source
commit identifies the complete source tree.

The published 0.4.2 downloads, their source, captured compiler observations and
known partial Coverlet coverage remain historical evidence. This change does
not replace those assets, install an update on the owner's PC, repair Docker,
alter existing accounts, or permit target execution outside an isolated worker.

Any eventual fresh downloads remain subject to checksums, source-bound release
gates and actual platform acceptance. Launching an extracted package is distinct
from testing an operating-system installation or upgrade transaction.
