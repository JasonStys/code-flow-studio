# Code Flow Studio 0.4.3 — C# coverage exit preservation

By Jason Stys. This source update corrects C# instrumented coverage. Hosted
compiler, security and native-package checks passed for the reviewed source; see
the [dated validation report](../reports/csharp-coverage-2026-11-10.md) for exact
sources, runs and measurement limits. Installers and portable archives are
assembled by the guarded release workflow, tested on each native operating
system and accompanied by SHA-256 checksums and embedded source metadata.

The new worker retains a C# target's actual exit status separately
from Coverlet's collector status. Normal compilation and approved-case results
remain independent of instrumented coverage. Current validation must distinguish
expected exits 0, 1, 2, 7 and 255 from an unexpected application fault, including
execution through the authenticated API and encrypted-history recovery.

Product, runtime, UI, package and worker-image identities advance to 0.4.3. New
packages must include the reviewed `csharp_coverage_bridge.py` resource and match
its source digest during actual packaged-application acceptance. Metadata schema
1 keeps its existing Node-analyzer-only `worker_sha256` field; the exact source
commit identifies the complete source tree.

The published 0.4.2 downloads, their source, captured compiler observations and
known partial Coverlet coverage remain historical evidence. The 0.4.3 update
keeps the same application identity and account/vault format; no account or
history migration is introduced. Back up private data before upgrading and quit
the app cleanly so an unlocked workspace can be sealed. Existing credentials
remain valid. Private data stays outside the installation and repository.

The release gate now requires successful compiler acceptance, validation, native
packages and all three full-main CodeQL analyses for the exact source. Independent
final download/installer acceptance precedes publication. Packages are unsigned;
no signing or notarization is claimed.

This update does not install, start, repair or rebuild Docker. Compilation still
requires a working isolated engine and a separately prepared matching
`code-flow-worker:0.4.3` image. Without it, editing and review remain available and
execution is explicitly blocked. Do not run source directly on the host as a
fallback. Launching an extracted package is distinct from testing an
operating-system installation or upgrade transaction.
